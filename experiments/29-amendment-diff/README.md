# 29-amendment-diff：修法比對——給雲端模型新版條文，它找得到舊版對應的那一條、說得出改了什麼嗎

## 1. 想回答的問題

給 Claude Haiku 5.5／Opus 5.5 一支只能查**舊版**（民國 110-03-17 修正）《用戶用電設備裝置規則》的搜尋工具，題目附上**新版**（114-05-09 修正）某一條的全文：它答得對「這一條在舊版是第幾條」「內容有沒有改」「某個數值從多少改成多少」嗎？答錯時，是**找不到**對應的舊條文，還是找到了卻**讀錯**差異？

## 2. 怎麼做

**為什麼做**：01–28 的題目都只問「現在這一版規定什麼」，27、28 已做到頂（Opus 有答案的 127 題全對；28 加五部別的法規當干擾，連固定檢索的撈全率都沒掉）。這次換一種難法：同一部規則的新舊兩版，文字大多一樣、條號全部重排（114 年是全案修正），模型要靠內容找到對應的舊條文，再說出差在哪。模擬的情境是「手上只有兩版全文、沒有官方對照表」（CNS 標準、規格書改版都是這樣）；官方的修正條文對照表這次只拿來當標準答案。

**計畫**：跑前寫好，過了五階段的獨立審查（十個沒看過對話的 agent），Mike 2026-11-07 核准。

**別人怎麼解的**（2026-11-07 讀過原文）：
- **"Asking For An Old Friend"**（ICAIL 2026，arXiv 2605.23497）：312 題德國法條問答，三類（知識截止後的修法、問舊版、多條舊版），四種設定；兩種 RAG 都先用日期過濾、**只給模型當時有效的那一版**，沒有新舊並排；閉卷 24–50%、RAG 72–87%。建題時把只改文字不改實質的修法排除。→ 它沒碰的兩件正是這次要做的：兩版並排比差異、只改文字算不算改。
- **RegTrack**（ACL 2026 SRW）：6 部歐盟法規、4,772 對條文，六類修正（沒改 74%、只改文字 1.5%、只改引據 0.2%、實質 5.6%、新增 14%、刪除 4%）。**找新舊對應：BM25 0.33、Levenshtein 0.70、dense 編碼器約 0.80、LLM 0.37–0.71**；分類 LLM 最強（F1 0.86–0.92）。→ 舊版索引選 dense 有數字支持；「只改引據」是獨立一類、不算修改，跟 T2 的定義一致。
- **LegDiff**（ACL 2026 SRW）：俄文法規段落級比對；字元 diff F1 21.9，GPT-5.2 55.7、Claude Opus 4.6 48.9。→ 判「有沒有改」不能靠字元比對。
- **CLaw**（arXiv 2509.21208）、**LexKairos**（arXiv 2608.09106）：版本與時間軸題，模型常答到錯的版本。→ 閉卷預期偏低的依據。
- **搜了沒找到**：中文法規、整部條號重排之後，用官方對照表當標準答案、量「自己查舊版」的受控實驗。

**資料**（`fetch_versions.py`，2026-11-07 抓；`corpus/manifest.json` 記網址、日期、sha256）：
- 新版：01 的 `corpus/law.pdf`（1,014 條）經 pypdf 6.21.3 抽字，存成 `corpus/new-1140509.txt`。
- 舊版：全國法規資料庫歷史條文頁，1,079 條（含 13-1 這種條號），`corpus/old-1100317.txt`。沿革頁顯示 110-03-17 到 114-05-09 之間沒有別的修正。舊版附表網頁沒有，**這次只問條文，不問表裡的數字**。
- 修正條文對照表：PDF 1,081 頁、15.7 MB（放 `data/`，不進 git）。前 916 頁是條文，三欄（修正條文／現行條文／說明）；**第 917 頁起是附表、附圖的新舊對照**（橫式），這次沒用，記下來。

**切對照表**（`compare_table.py` → `corpus/rows.json`，1,493 列）：PDF 畫了格線，列就是兩條橫線之間。幾個坑，每個都有測試：
- 條號標頭只認格子左邊界、而且上一行是句尾的字詞，否則「依第一百五十二條\n規定」這種換行的引用會被當成標頭（第一版就錯在這）。長標頭會折行（「第二百五十二條之三第二」／「項」），要接下一行讀（第二版錯在這，跑前審查抓到：3 列舊欄有字卻被當成新增）。
- 格線跟著「有條文開始」的那一欄畫，另一欄的文字會跨線流下去：新 281 的文字跨過舊 396-74 開始的那條線（整併），新 872 開始時舊欄還在流前一條的尾巴。規則：一欄在線前接續的文字歸上一列；「舊條開始、新文接續」的格子，說明欄沒有新起一段就併入上一列。
- 官方表格會把兩條舊條文放進同一格（新 370 ← 舊 97＋96）、一條舊條文拆到好幾列、或只對到一條的「第一款」（記 `old_part`）。新增的條舊欄必須是空的，刪除的條新欄必須是空的（測試）。
- 測試鎖住：新版 1–1,014 條各恰好出現一次；舊版 1,079 條各至少出現一次；抽 30 頁沒有字跨欄；合成的小表格驗每條規則。
- 統計：條文列 1,324；一對一 716、新增 248、刪除 310；舊條文出現在不只一列 36、一格兩條以上舊條文 50（說明欄都寫整併）、只對到部分 51。
- 對齊：一對一的列，舊欄文字去掉標頭、折掉標點與空白後跟舊版網頁同一條逐字相同的比例 **96.0%**（997 列中 957 列；門檻 90%）。對不上的多是歷史條文頁打錯字（405「原源」）、PDF 少一個「五」這種單字差異、或格子裡混進節名。

**兩版的寫法不同**（`textnorm.py`）：舊版數字按位寫（六○○伏、一五○、二‧五）、新版用十百千（六百伏特、一百五十）；引據條號、表號跟著重排（第十六條 → 第二十五條、表一六～三 → 表二五～二）。比對前把數字讀成數值、引據遮掉、標點去掉，兩版「同一條沒改」才會相等。

**題目**（`make_questions.py` → `questions.jsonl`，112 題；答案全部來自對照表，亂數種子 0，按章分層）：

| 種類 | 問法 | 標準答案 | 題數 |
|---|---|---|---|
| T1 條次對應 | 新版第 N 條在舊版是第幾條？沒有對應就答新增 | 一對一列的舊條號；新增列（舊欄空、說明寫本條新增） | 60（新增 10） |
| T2 有沒有改 | 跟舊版對應的那一條比，條文文字有沒有被修改？用詞、句子的改動都算；條號、引據、數字寫法、標點與分款編號不算 | 折疊後文字相等 → 沒改（20 列，全收）；不相等且說明欄有修正字眼 → 有改（673 列抽 20） | 40 |
| T3 數值改了 | 它規定的「某個量」舊版、新版各是多少？（題目指定單位） | 數值集合不同的 143 個候選列，人工逐條看，留下真的改了值的 **12 題**（其餘是單位換寫、新增或刪除數字） | 12 |

- T2 的規則跟計畫不同，跑前就改了：計畫寫「只看說明欄」，但說明欄不是乾淨的分類器——只寫「條次變更、移列」沒有修正字眼的列有 56 列，其中 43 列文字其實不一樣（說明欄用一段話解釋改了什麼，不用「修正」這個詞）。改成以文字比對為主、說明欄只用來確認「有改」；兩種訊號不一致的 3 列不出題。這部規則是全案修正，**真的沒改的只有 20 條**，所以 T2 是 20＋20，不是 30＋30。
- T2 問的是「文字有沒有被修改」，不是「規定有沒有實質改變」：試跑時一題只改了「選定」→「有」、「損害」→「損壞」、但書改寫成另一項，兩個模型都答沒改。「實質」與「用詞」的界線切不乾淨（「大於」→「超過」算哪種？），所以題目明寫用詞改動也算，正解就是文字比對本身。這讓 T2 偏向「找得出差異」而不是「判斷重要性」，README 第 5 節記著。
- T3 的「某個量」怎麼寫、數值對不對，跑前另一個 agent 只看那一列核對。
- 題目都附新版那條全文；新版不建索引。新版 PDF 抽出的條文帶「項」編號（「1　依本規則…」，250 條有），舊版網頁和對照表都沒有，出題時拿掉，不然 T2 會把它當成差異。

**尺**（`score.py`）：T1 條號正規化後相等（「第十六條」「16」「第 16 條」同一個；新增要答 `found: false`）；T2 `changed` 相同；T3 兩個數都在正解的 1% 內（正解 0 要完全相等），新舊對調另記；被停或解析不了算錯。

**主檢定**（跑前宣告；T2＋T3 共 52 題；按題與按章兩種 bootstrap 的 95% 區間都不含 0 才算分得出）：`oracle − agent`，Haiku、Opus 各一個。只有這兩個。

**只描述**：三種題各自的答對率；舊版正解撈全率（正解舊條在搜尋回傳的聯集裡）與「撈到／沒撈到 × 答對／答錯」；T1 答出的舊條號在不在查到的標籤裡；閉卷答對率；查詢次數；T2 答「有改」的比例；T3 對調；花費；Haiku 兩次同答；漂移探針（`drift.sh`：用 27 自己的 `run.py` 重跑 27 的 20 題，比同答數）。

# 21-lookup-segment：查表工具回整欄——替小模型把該看的段攤開

## 1. 想回答的問題

查表工具從「只回模型點的那一格」改成「回那張表那一欄的所有列」，小模型在 C1／C4／C5 答對比 19 的 fix 多多少？

## 2. 怎麼做

**為什麼做**：19 的小模型輸在「選哪幾列」（C4 分段只查一段、C5「以下」讀成下面那段），20 的 Opus 用同一支工具 75 題全對、選錯列 0。小模型點錯列時，工具只回它點的那格，它看不到旁邊那段。把整欄攤開，模型就算點偏了，正解格也在眼前。

**別人怎麼解的**：
- **TabSQLify（arXiv 2404.10150）**：先挑子表再答；錯誤分析裡「漏掉該要的列」佔 WikiTQ 錯誤 56%、TabFact 32%——跟 19 的「分段只查一段」同型。
- **Chain-of-Table／DATER**（arXiv 2412.12386 的分析）：用 `f_select_row` 挑列，常挑錯或多挑。
- **PieTa（ACL 2026）**：子表分段挑、逐步合併，不靠模型一次選對全部列。
- 共同方向：挑子表時寧可多給（召回優先），讓模型在子表裡選。
- **搜了沒找到**：中文法規表、分段累進表的子表選取研究。

**計畫**：跑前寫好，Mike 2026-11-03 核准（跟題庫更正同一份）。

**設計**（比計畫更緊的一處）：seg 不重問第一步，**直接用 19 那一列 fix 的第一步回覆**（模型點了哪些表／列／欄），用同一支比對重新解析，只把第二步看到的內容換成整欄，再問第二步。所以 seg 跟配對的 fix 指的格子完全一樣，差別只有工具回什麼。gpt-oss：seg 配 fix、seg-2 配 fix-2；qwen3：seg 配 fix。

**回傳規則**（`lookup.render_segment`）：表、欄都對得上 → 回整欄（每列一行 `表｜列｜欄 = 值`，模型點的列標「← 你查的」，同一欄只回一次）；欄對不上但列對得上 → 回整列；都對不上 → 照 19 說「查無」；表的註照附。不呼叫 `rules.py`，分段怎麼累進、選哪段仍是模型做。

**格與模型**：`qwen3:8b`（think 關）、`gpt-oss:20b`（think low），host ollama，設定、digest 照 19（開跑前檢查）。fix／fix-2 是 19 的列照抄（`reused_from: "19"`），用同一支 `score.py` 重評。開跑前 qwen3 照抄的第二步重問 2 題、要一字不差。

**題庫**：19 的同一份，5 題 `defect` 不計分（見 20 README 第 3 節更正）：有答案 75 題、全部 91 題。

**主檢定**（跑 21 之前宣告；答對嚴格，有答案 75 題，按題與 cluster 兩種 bootstrap 都過才算分得出）：
1. qwen3 seg − qwen3 fix
2. gpt-oss seg − gpt-oss fix

描述、不下判定：gpt-oss seg-2 − seg（雜訊底線）、seg-2 − fix-2；按鏈；正解格在不在回傳裡（`posthoc.shown`）；讀錯列（答錯且算式用了回傳裡別列的值，`posthoc.read_slip`）；回傳字數。

**跑前審查**（另一個 agent，用假的模型把整串離線跑一遍）：配對、第二步提示、比對都對——288 列 fix 的查詢重新解析 0 處不同，第二步提示除了依據之外跟 19 逐字相同（第二步的標籤仍寫「查到的格子」，刻意不改）；正解格在 seg 裡沒出現的題由第一步決定、跑前就算得出來。擋下兩個會讓描述數字錯的地方，已修並加測試：
- 報表沒列 seg 格（`report.py` 的 CONDITIONS 沒改）。
- 「讀錯列」與命中欄位在整欄下會機械性變多：整欄把每一列都標成看到了、÷100 被當成別列的 100、正解列別欄的值被當成別列。改成：命中只算「正解值有出現在正解列上」（`run_read.honest_labels`，`cells.py`）；讀錯列只算「正解格看得到、算式卻少了正解值、用了正解欄別列的值」，100／1000 不算。

**跑前就定的數**（由第一步決定，不是預期）：正解格在回傳裡的題，fix → seg：qwen3 47 → 71、gpt-oss 51 → 69（fix-2 → seg-2：50 → 68），有答案 75 題。

**預期**（跑前寫；讀錯列的基準是審查後改的）：
- 主檢定兩模型各 +.05～+.15。
- 讀錯列：如果模型看到整欄還是照 fix 那樣答，會是 qwen3 12、gpt-oss 2（fix-2 配的 5）——這是「沒變聰明」的基準。預期 seg 比基準少：qwen3 ≤ 8、gpt-oss ≤ 3。
- C4 升最多。

**正式跑**：2026-11-03 08:52–09:30，mini，ollama 0.40.2，digest 同 19（開跑前檢查）。新跑 288 次第二步（qwen3 seg 96、gpt-oss seg／seg-2 各 96），0 失敗；照抄 19 的 fix 列 288 列。漂移探針：qwen3 照抄的 fix 重問 2/2 一字不差、seg 2/2；gpt-oss fix 1/2、seg 2/2、seg-2 1/2（gpt-oss 本來就不逐字重現）。

## 4. 結論

**查表工具回整欄，gpt-oss 答對 +.13（C4 +.30），兩次跑都一樣；qwen3 不動——它看得到正解格了，還是把分段負載乘一個係數，卡在規則不是卡在看不到。**

## 5. 沒做到的、下次想試的

- **qwen3 要的是規則，不是更多資料**：分段累進寫成函式讓模型只填參數（16 第 5 節提過），或在提示裡寫明「分段各乘各的再加總」。C4 是最直接的試驗場。
- **seg 沿用 19 的第一步**：模型若知道會回整欄，可能點得不一樣；這次刻意不重問，只量「回什麼」。
- **回傳變長**：qwen3 平均 187 → 1,046 字（最長 3,181），gpt-oss 147 → 747；這個題庫的表最多 30 列，表更大時要改成「回相鄰幾列」。
- **讀錯列**只看算式裡的數字；答對但引文是別列的不會抓到；100、1000 不算（百分比、千）。
- 該棄答的題沒進主檢定；命中欄位在棄答題上照整欄標記（會多算），只是描述。
- 第二步的標籤仍寫「查到的格子」，為了提示跟 19 一致沒改。

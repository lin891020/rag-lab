# 02 JSON 固定輸出：提示詞拜託、json-mode、schema 約束，哪種讓本機模型吐的 JSON 最可靠

## 1. 想回答的問題

給本機模型一段法規和一個只問一個數字的問題，要它回固定欄位的 JSON：只用提示詞拜託、開 ollama 的 json-mode、還是用 JSON schema 做約束解碼，格式錯誤率和值答對率各差多少？

## 2. 怎麼做

**題庫** `questions.jsonl`：66 題（條文 44、表格 22），全部從 01 的題庫挑「答案是單一數值」的題，多值題拆成子題（a01 → a01a 1.25 倍、a01b 3.5 mm²、a01c 2.0 mm），正解寫成 `{"value", "unit", "alt"}`，`alt` 是同義的（值, 單位）組合（1 m = 100 cm = 1000 mm、75% = 0.75）。正解文字直接讀 01 的 `corpus/`，不複製。Mike 2026-10-28 抽查 a01b、a18c、a26b、t09b、t13b（問法與正解），另看了模型答錯的 t15、a31a、t14b 確認正解沒標錯，都 OK。

**條件**（4 種 × 2 模型），三個開卷條件**送的 prompt 逐字相同**（system：台灣電機技師；user：欄位說明 + schema 原文 + 正解條文或表格 + 問題），只差 API 的 `format` 欄位。這是 Tam et al. 2024 被批的點，刻意避開。

| 條件 | `format` | 給正解文字 | 角色 |
|---|---|---|---|
| closed-book | `"json"` | 否 | 雜訊底線：不看文件能猜中多少 |
| prompt-only | 無 | 是 | 盲測基線：實務上最常見的「請回 JSON」 |
| json-mode | `"json"` | 是 | 只保證是合法 JSON |
| schema | JSON schema 物件 | 是 | 文法約束解碼，欄位與型別鎖死 |

schema 固定 `{"quote": 原文那句, "value": 數字, "unit": 字串}`，quote 放最前面讓模型先引用再給數（dottxt 2024 的作法）。

**模型設定**：temperature 0、seed 0、num_ctx 8192、num_predict 1024。qwen3:8b `think:false`；**gpt-oss:20b 關不掉思考**（ollama 0.40.2 無視 `think:false`，開 schema 時思考吃光 num_predict、content 變空），所以 gpt-oss 四個條件都用 `think:"low"`。

**判定**（`score.py`，純程式，不用 LLM 當裁判）：`parse_ok` = `json.loads` 成功（先去 ``` 圍欄，另記 `fenced`）；`schema_ok` = 三個鍵都在且型別對；`value_ok` = 值相等（容差 1e-6）且單位在同義表內；`value_only_ok` = 值對單位錯（另報，不進結論）。單位同義表在 `score.py` 的 `UNIT_ALIASES`（mm² / mm2 / 平方毫米、VA / V·A / 伏安……）。

**五條規矩怎麼套**：雜訊底線 = closed-book；盲測基線 = prompt-only；信賴區間 = 重抽題目 2000 次的 bootstrap 95%，條件之間報配對差距；記版本 = 下表；漂移探針 = 跑完每格重打 2 題（16 次），content 逐字相同 16/16。

- gpt-oss 3 題：a15b 單位寫 V（值 90 對）；a30b 把「○‧一秒」讀成 1 秒；t17 讀到表註的 80 mm²。

## 4. 結論

**在「給了依據、只要一個數字」的題上，提示詞拜託、json-mode、schema 三種逼法產生的 JSON 一模一樣（qwen3 66 題逐字相同），格式錯誤率三者都是 0，值答對率也都是 .88（qwen3）／.95（gpt-oss），差距 +.00；逼法選哪個沒差，錯的全在讀表格與讀數字，不在格式。**

次要的：閉卷只有 .05–.08，答對確實靠讀文件；schema 沒有比較省 token（78 vs 81），因為輸出本來就只有二十幾個 token；gpt-oss 在 ollama 0.40.2 關不掉思考，開 schema 又 `think:false` 會回空字串，這是工程上真正會踩到的坑。

## 5. 沒做到的、下次想試的

- **題目太簡單，約束根本沒出手**。三個條件輸出相同，表示文法從頭到尾沒改過任何一個 token。要看出差別得把題目弄難：巢狀 schema、enum、長清單、多個數值一起填，或者不給正解塊、給整章讓模型自己找。Castillo 的結果是「看任務」，這裡只測了最簡單的任務。
- **攤平的表格還是最大的錯誤來源**：qwen3 錯的 8 題有 7 題是表格，跟 01 的發現一致。下一步不是換逼法，是把表格餵成 markdown 或逐列帶表頭，再量一次 value_ok。
- **中文數字寫法**：「○‧一秒」被 gpt-oss 讀成 1，「三‧五」在探針時被讀成「最小整數 4」。prompt 已寫「照原文數值」，還是會錯；可試先把 `‧` 正規化成 `.`、中文數字轉阿拉伯數字再餵。
- **qwen3 的 think 開著再跑一次**：Thinking Before Constraining (2026) 說先推理再約束比較好，這裡 qwen3 是關掉思考跑的；gpt-oss 則只能開著。兩個模型的思考設定不同，模型之間的 .88 vs .95 不能直接比。
- **沒測 retry**：Tam et al. 說「解析失敗就讓 LLM 重排一次」成本低效果好。這裡失敗率是 0，retry 沒東西可修，但在難題上要補。
- **單位同義表是手寫的**：跑完才加了 V·A。有新模型就會有新寫法，value_only_ok 那欄是用來抓這個的。

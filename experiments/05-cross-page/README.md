# 05 跨頁表格：續頁沒有表頭時，逐頁讀、兩頁併排餵、還是用規則接回去，模型差多少

## 1. 想回答的問題

109 張附表裡有 3 張跨頁（表五六 2 頁、表五八七～一 2 頁、表五八七～三 3 頁），續頁都**沒有重複表頭**，而且有被頁界切斷的合併儲存格（續頁第一欄空白）和被切成兩半的格子（表五八七～三 第 2→3 頁「不位於第一種場所或第二種／場所、1 區或2區」）。一個按頁切塊的 pipeline 看到的是沒標題、沒表頭、第一列被當成表頭的半張表；用幾何規則把續頁接回去，答對率差多少？規則在另外 106 張表上會不會誤接？

## 2. 怎麼做

**別人怎麼解的**（`docs/research/2026-10-29-cross-page-tables.md`）：Docling、pymupdf4llm、pdfplumber、Camelot 都不合併；會合併的 MinerU、Azure、AWS Textract、Doctra 用的是同一組幾何規則——前表到頁底、後表在頁頂、中間沒有文字、寬度與欄界對齊、續頁沒有標題；PubTables-v2（2025）說 38% 的表跨頁、用 ViT 分類 F1 .99，合併後 GriTS_Con .58→.68。**沒找到**任何量過「續頁沒表頭對下游答題的損失」的實驗，這一題補這個洞。

**規則**（`tables.py` 的 `is_continuation`，照上面那組寫）：前一頁的表 bbox 底 ≥ 0.8 頁高且表下方沒有字；本頁的表頂 ≤ 0.2 頁高、表上方沒有字、本頁沒有「表○○」標題行；表寬差 < 10%；本頁 ≥ 60% 的欄界在 3 pt 內對得上前一頁的。**合併**（`merge_pages`）：各頁的格子對齊到所有頁欄界的聯集（表五八七～三 第 3 頁多一欄，第 1、2 頁的格子自動變成 colspan），續頁第一列若只有一格有字就接回前一列同欄（被切斷的格子），續頁第一列前面的空格補前一頁最後一列同欄的值（被切斷的合併儲存格）。接完走 03 的管線（去註、表頭深度、markdown）。

**偵測的評測**（`detect.py`）：正例 = 同一份 PDF 相鄰兩頁都有表的 4 對；負例 = 第 i 張附表最後一頁接第 i+1 張附表第一頁、頁碼改成連續（模擬整份法規一個 PDF 連著看），108 對。

**答題**（`run.py`，prompt、schema、模型設定同 02–04）：38 題，13 題 ctrl 答案在第一頁（6 題照抄 03 的表五六題、7 題新出），25 題 cont 答案在續頁；正解對 PDF 原圖標。四個條件：

| 條件 | 餵什麼 | 角色 |
|---|---|---|
| closed-book | 不餵 | 雜訊底線 |
| page | 只餵答案所在那一頁，逐頁讀：續頁沒標題、第一列被當表頭 | 盲測基線 = 按頁切塊的 pipeline 只撈到那一塊 |
| pages | 該表每一頁各自一塊、依序並排（第 1 頁有標題與表頭） | 按頁切塊但每塊都撈到 |
| merged | 規則接回去的整張表 | 本實驗的提案 |

4 條件 × 2 模型 × 38 題 = 304 次呼叫；漂移探針每格重打 2 題。閉卷的 區 答案只有 0/1/2 三種，猜中率本來就高，所以看差距不看絕對值。**Mike 抽查名單**：c11、c16、c19、c23、k08 的正解。

- 6 題「要靠欄名」的題（表五六 續頁 26–30、31–40…列）：**接回表頭沒有救**——qwen3 merged 答 32、30、32（讀到別列的 C 行），gpt-oss 答 32、28、26。接回去之後它變回 04 那張 30 列的範圍表，04 已經量過兩個模型在範圍列上讀不準。只餵續頁那 5 列、沒表頭，反而對 3–4 題：表小，模型靠位置猜。
- **兩頁各一塊並排是最差的**：−.13 分得出，兩個模型一樣。第二塊沒表頭、第一塊有，模型在 2.5k 字裡要自己對欄，連第一頁的對照題也掉（k04、k05 兩個模型都錯）。
- 閉卷 gpt-oss .18：區 只有 0/1/2，它又認得 NEC 514 那張表（這張是它的翻譯），所以 cont 題閉卷 .24。看差距不看絕對值。
- 漂移 14/16，差的 2 次都是 gpt-oss 的 k01（closed-book、pages），同 03／04。

## 4. 結論

**續頁沒有表頭的損失只出現在「答案要靠欄名定位」的題上（這份題庫 25 題裡只有 6 題），而在那 6 題上規則接回表頭也沒救到（qwen3 1/6、gpt-oss 2/6），因為接回去就是 04 量過讀不準的 30 列範圍表；答案寫在格子文字裡的 19 題，少了表頭照樣全對。真正分得出的是「每頁一塊並排餵」比「只餵續頁」差 −.13（兩個模型都分得出）——按頁切塊的 pipeline 多撈一塊反而害。偵測規則本身可靠：4/4 真跨頁全接、108 個鄰表負例 0 誤接。**

對 pipeline 的意思：跨頁要合併，但理由是「不要把兩塊沒對齊的表一起餵」，不是「補表頭就會答對」；補了表頭之後的問題是 04 的問題（範圍列、寬表、表註）。

## 5. 沒做到的、下次想試的

- **只有 3 張跨頁表**（4 個頁界），規則的 4/4 與 0/108 是在這份法規上量的；別的版型（續頁重複表頭、續頁有「續表」字樣、頁首頁尾有頁碼）沒碰到，規則對「表上方沒有字」那一條在有頁首的 PDF 上要改成「只允許頁碼」（Azure／AWS 的作法）。
- **合併的兩個修補只在續頁第一列做**：被切斷的格子如果在中間列（pdfplumber 把一格拆成兩列）接不到；MinerU-Popo 用模型做格子級合併，準確率 92.7%。
- **表五八七～一／三 的表頭深度要手動指定 1**（第一欄是兩層標籤，03 的規則看成 4 層）。
- **沒做「續頁重複表頭」的刪除**：這份法規沒有這種頁，程式也沒寫。
- **page 條件的「第一列當表頭」是 Docling #2976 回報的行為**，不是每個工具都這樣；pdfplumber→pandas 也是。沒試「續頁全部當資料、表頭留空」的版本。

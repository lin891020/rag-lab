# 04 範圍列與寬表：把範圍展開成上下限、只餵問到的列，救不救得了 03 剩下的錯

## 1. 想回答的問題

03 之後剩下的讀表錯誤集中在「列是範圍的表」（表九三～一「38 - 50 → 14」）和「7 欄 21 列的寬表」（表二五～二）。把範圍格展開成「下限／上限」兩欄、或只餵選列器挑出的三列，值答對率各升多少？

## 2. 怎麼做

**語料**：03 的 17 張表，`build_corpus.py` 把 03 的格子（幾何算 span 後）攤成 `corpus/tables.json`（標題、欄名、資料列、註），`run.py` 只讀它，不需要 PDF。基底格式用 **markdown**（03 兩個模型平均最好、字元只有攤平的 1.7 倍；qwen3 在 03 是 kv 略高但分不出，這是 Claude 的決定）。

**兩招**（`tables.py`、`select_rows.py`）：
- **範圍展開** `expand_ranges`：某欄的資料格 ≥ 半數能解析成範圍（「38 - 50」「30以下」「41以上」「超過 80 - 200」「3,001至120,000」「超過120,000」；純數字算點、不展開）就在右邊插「欄名／下限」「欄名／上限」兩欄，原欄保留。17 張表第一欄的全部寫法都有測試。
- **選列** `select_rows`：每個資料列的 kv 文字對題目做字二元組 BM25（k1 1.5、b 0.75，照 01），題目裡的數字（含「50,000」「2.0」）落在某格的範圍內該列加分，先比落點數再比 BM25，取前 3 列、保持原順序，子表 = 表頭 + 這 3 列 + 註。**不看正解**；每題另標 `row`（正確列的前幾格，對 PDF 原圖標）只用來事後算「正確列有沒有被留下」（row recall）。選列永遠在未展開的表上做，所以 2×2 乾淨：

| 條件 | 印上下限欄 | 只餵 3 列 | 平均依據字元 |
|---|---|---|---|
| closed-book | — | — | 0（雜訊底線） |
| md | 否 | 否 | 590（盲測基線 = 03 的 markdown，重跑） |
| md+range | 是 | 否 | 679 |
| md+rows | 否 | 是 | 294 |
| md+range+rows | 是 | 是 | 332 |

**題庫**：03 的 82 題逐字照抄（測試保證），加 `row` 和 `cat`（range 39、wide 19、range+wide 6、plain 18，照表分）。事先宣告的假設：範圍展開救 range 類、選列救 wide 類。Mike 抽查名單：t01、n54、n17、n28、n26 的 `row`。

**其他**：prompt、schema、模型設定、判定（`score.py`）全部同 03。820 次呼叫 49 分鐘。

**五條規矩**：雜訊底線 = closed-book；盲測基線 = md；區間 = bootstrap 95%（2000 次）、配對差距；記版本 = 下表；漂移探針 = 每格重打 2 題，**19/20 相同**（差的是 gpt-oss md+range+rows 的 t01）。

錯在哪（`results/scored.jsonl`）：
- **表九三～一的錯不是範圍解析，是表註**。n54／n55／t17／n56 在 md+range 下，qwen3 四題全答「80」，quote 抄的是註「超過 500 mm2 者不得小於 80 mm2」；gpt-oss 答「12.5」或「40.625」（把註的 12.5% 拿來算）。上下限欄把表變寬，模型反而更常逃到註去。
- **選列把表縮小，但註還在**，誘餌沒拿掉；gpt-oss 在 md+range+rows 下表九三～一 全錯。
- **寬表**：qwen3 的 n02／n03／n08（表二五 家族）四個條件全錯，選列有把對的列留下（recall 命中），它還是讀錯欄。問題在欄不在列。
- md 的 gpt-oss .91 比 03 同條件的 .95 低 3 題，跟漂移 19/20 同一個量級。

## 4. 結論

**範圍展開和只餵三列都沒有救到：四個配對差距的區間都含 0（qwen3 +.01、−.01；gpt-oss +.02、−.01），兩招合用在 gpt-oss 上反而比只展開差 −.09，分得出。03 剩下的錯主要是表註裡的數字（「80 mm2」「12.5 %」）把模型引走，和寬表讀錯欄；這兩招改的是列，不是這兩件事。**

次要的：選列的 row recall .95，字元只剩一半（590 → 294），準度沒掉，所以「縮小上下文」本身無害；閉卷 .05–.06，答對靠讀表。

## 5. 沒做到的、下次想試的

- **把註移出表格區塊**：註是最大的誘餌。試「表格」「附註」分兩段、附註標明「非查表值」，或乾脆不餵註（但有些題要註才答得了，例如 11 題用 B 行的 表五六）。這一題最便宜、最可能有效。
- **寬表的欄**：選列留對了列還是讀錯欄（qwen3 n02／n03／n08），下一步是**選欄**：用題目裡的「3 條」「7-9」對欄名做同樣的 BM25，只留問到的欄 + 鍵欄。
- **k=3 不夠**：題目有兩個以上數字時正確列會被擠掉（4/82）。k=5 或「落點命中的列全留」。
- **gpt-oss 數字波動**：同條件 03 的 .95、04 的 .91；要分出 ±.05 的差，82 題不夠，或每格跑 3 次取多數。
- **沒試兩段式**：先讓模型指出「落在哪一列」再回答（Table Meets LLM 的 self-augmented prompting）。

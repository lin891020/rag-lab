# 28-hosted-bigger-corpus：語料加大——多放五部相近的法規，雲端模型自己查還撈得全嗎

## 1. 想回答的問題

同樣 160 題、同一支 search 工具，索引從一部規則擴成六部（單位 1,159 → 2,497、字數約 2 倍），Claude Haiku 5.5／Opus 5.5 自己查的答對率比 27 掉多少？

## 2. 怎麼做

**為什麼做**：27 讓雲端模型自己查，撈全率 .77 → Opus 1.0、Haiku .93，答對 Opus 127/127，這批題到頂。27 第 5 節寫的最大保留是語料只有一部規則（1,014 條、109 張表），表名好查；實際系統會放好幾部規範，相近的條文變多，模型的查詢可能沒這麼準。這次只改語料大小。

**別人怎麼解的**：
- **Reimers & Gurevych**（ACL 2021，arXiv 2012.14210）：dense 檢索的誤判隨索引變大而增加，掉得比 BM25 快。→ 固定檢索（題目原文查一次）的撈全率應該會掉；這不用叫模型，免費量。
- **Cuconasu 等《The Power of Noise》**（SIGIR 2024，arXiv 2401.14887）：看起來相關、但沒答案的段落最傷答題，隨機段落反而無害。→ 干擾語料要挑同領域的，不是隨便湊大。
- **BrowseComp-Plus**（arXiv 2508.06600）：用固定語料評 deep research agent；語料加大十倍，主要結論沒變，檢索器越好、agent 查得越少。
- **LegalBench-RAG**（arXiv 2408.10343）：多份法律文件的檢索評測，要求準到片段；我們的「正解列撈全」就是片段級。
- **搜了沒找到**：中文法規、多部法規條號全撞的情況下，「模型自己查」對「固定檢索」的受控比較。

**會不會讓題目變兩可**（跑前另一個 agent 只讀檔查過）：五部法規裡沒有任何條文或表能讓這 160 題合理答出不同的值。沒有安培容量表、修正係數、電動機分路、需量因數；最像的是輸配電第 17 條「未提供過電流或故障保護時，設備接地 14 mm²」，前提跟題目不同。建築設備編第 1 條與職安規則有一條明文「依用戶用電設備裝置規則」，反而指回對的那部。

**索引**（`search.py`）：
- `big`：原本 27 的索引一個字不動放在前面，後面接五部的條文（一條一塊，標頭「章 / 節 / 第 N 條」）與附表卡片。新單位的標籤一律加 pcode（`J0030019:25`、`J0030019:表五○`），永遠對不上正解；撈全率只算原本那部的正解列（測試）。
- `big-name`：同上，每個單位與每張整表前面加一行《法規名》（10 的修法：「哪一份」題沒前綴 .21、有 .94）。
- 只放原本那部時，拿題目原文查，160 題的回傳跟 17 存的 cards 依據逐字相同（沿用 27 的測試）。
- bge-m3 digest `790764642607`；嵌入快取用自己的一份（從 01 的複製），不動 16／17／27 的。

**提示**（`prompts.py`）：27 的逐字，只把依據那行與工具說明的「《用戶用電設備裝置規則》」換成「法規庫（六部法規名，照 pcode 排）」，不說哪部適用。**沒改的、要記得的**：系統提示是 17 起沿用的「你是台灣的電機技師助理，熟悉屋內線路裝置規則與其附表」，屋內線路裝置規則是這部規則的舊名，等於提示了該查哪部。為了跟 27 只差一個變因，照舊不改。

**條件與次數**（都是模型自己查，最多 5 次、8 輪，迴圈跟 27 一樣）：
- `agent-big`：Haiku 兩次（`-2` 當雜訊底線）、Opus 一次。
- `agent-big-name`：同上。
- 基線讀 27 的 `agent` 列（同模型、同一把尺重算；測試鎖住跟 27 算出來的一樣）。
- 不叫模型的量測：題目原文查一次（cards），在 base／big／big-name 三種索引的撈全率。
- 每題記查詢、輪數、搜尋回傳的標籤聯集、聯集來自哪幾部法規、token。累計超過 US$25 就停。簽章含建好的索引內容（每個單位的字與標籤），索引一變舊列就過期。

**主檢定**（跑前宣告；答對嚴格，有答案的 127 題；按題與按 cluster 兩種 bootstrap 的 95% 區間）：
- agent-big − agent（27），Haiku、Opus 各一個。區間不含 0 才算「變了」；分不出時，兩種區間的下緣都 > −.05 才說「沒掉超過 .05」。

**描述、不下判定**：撈全率；big-name − big；查幾次；查回別部法規的比例；答錯的題查到哪幾部；引句與數字在不在查到的文字裡；每題花費與秒數；該棄答的 28 題；選小一級；Haiku 兩次同答。

**預期**（寫在計畫裡，核准時就定了）：
- 題目原文查一次的撈全率 .59 → .50–.57。
- agent-big：Opus 答對 .95–1.0、Haiku .88–.96；兩個主檢定都分不出，Opus 下緣 > −.05，Haiku 不一定。
- 平均查詢次數多 0.2–0.5 次；每題花費多 10–30%。
- 錯的集中在撞號的條文與「導線、接地」相關的表；big-name 比 big 多對 0–.03。

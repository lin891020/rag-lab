# 16 規則查表接計算：給一個負載，撈對規則與表格列、算出一個數，L0／L1／L2 各掉在哪一步

## 1. 想回答的問題

給一個用電設計的情境（導線、周溫、馬達、負載、過電流保護），純模型（L0）、加知識庫（L1）、再加計算工具（L2）各能答對多少、**選小（不安全）**多少、該棄答時棄答多少；錯的落在撈錯列、抄錯值、算式選錯、算錯哪一步。知識庫是公開的《用戶用電設備裝置規則》全文與 109 張附表。

## 2. 怎麼做

**別人怎麼解的**：
- **AECBench**（arXiv 2509.18776，AEC 領域 4,800 題、五個認知層級）：模型最弱的是「讀規範裡的表」與「計算」；沒做 RAG 對閉卷的比較。
- **錯誤歸因**：SEER（arXiv 2310.06675）對 TAT-QA／FinQA 的分析——取值錯 63%／76%、算式選錯 30%／45%、執行錯 0%／4%。工具只救執行錯；這裡把四類分開數，不然 L2 的收益會被誤判。
- **程式幫算（PoT）**：FinQA／TAT-QA 的標準基線；小模型＋生成程式（arXiv 2512.13323）TAT-QA 精確率 60 → 71。L2 用「模型吐算式、程式算」，不是真 tool calling（`rag_lab.ollama.chat` 沒有 tools，第 5 節）。
- **找欄位再精算**（arXiv 2601.18012）：報精確與容差兩種指標、記 schema 合規。→ 兩把尺（1% 容差、梯上的級）並列。
- **本機**：03（表格 kv／markdown 比攤平 +.12～+.22）、04（整張表餵進去 .79／.91，列召回 .95，錯在抄到註解與讀錯欄；17 張乾淨表）、11（`found`）、10（尺、`budget_evidence`）、15（cluster bootstrap、獨立 agent 出題與核題）；梯級評分語意（match／acceptable／error／critical）。
- **搜了沒找到**：針對電工法規導線選型的 LLM 評測；台灣用電規則的任何 LLM 評測。

**計畫與審查**：計畫 `docs/superpowers/plans/2026-10-30-16-rule-lookup-compute.md`（Mike 2026-10-30 核准；計畫階段監察員 14 條、必改 8 條都併了）。**跑前獨立審查**（另一個 agent，重現 span 257/257、excerpt、塊數；測試 25/25）抓到 5 處、跑前修掉：① 選型題的歸因把「選到那列的載流量不在引句」記成抄錯值，選型錯永遠量不到 → 選型題不要求 gold 列的載流量；② 表五二「手術室不得適用」只在表的註，索引裡沒有、oracle 也沒給 → 每張乾淨表的註自成一塊（`表號|註`），hospital-na 的 gold 列指到註，而且不加「分段累進」那句（會叫模型套用）；③ `calc` 把「= 29」尾巴、「35%」判無效、「2×10³」NFKC 後靜默算成 206 → 截在 = 前、% 換 /100、上標拒絕；④ `rows_all_hit` 把棄答題（gold 是空白格或理由）算進去，oracle 寫死命中 → 只算可答題；⑤ 出錯的呼叫被 `done_keys` 當做完 → 續跑時重做。另記：L1-fixed 塊 ≤999 字、預算 1,500，實際是 top-1，C2／C3 兩張表的 gold 列結構上放不進同一塊——這是固定切的真實代價，不是檢索差；第 25 條 600 字窗含第五、七款，第 60 條全文 341 字含前提。

提示：11 的 `found` 規則（找不到、表沒這格、規定不適用 → false）；可換算、要寫算式；quote 照抄用到的規定句或表格列。預算 1,500 字（兩列加一條規則要塞得下），第一塊一定讀（10）。gold 用塊的標籤判（條號、`表號|列鍵`），不用文字包含。模型設定同 09–15；漂移每格 2 題；每格前 3 題 log 秒數。

**尺**（`score.py`）：數字題相對誤差 ≤ 1%；選型題在表自己的梯上：等於 match、大一級 acceptable、大兩級以上 error、**小於 critical**；棄答題 `found:false` 對、硬答錯；單位嚴格／寬鬆（10）。**主檢定**（事前宣告，每模型 6 個）：L1-fixed − L0、L1-struct − L1-fixed、L1-oracle − L1-struct、L2-oracle − L1-oracle 各全 160；L2-struct − L1-struct 用 C2+C3+C4 合併 96 題與全 160。鏈內差距只描述。bootstrap 2000 次 seed 0，按題與**以鏈分層、鏈內按 (表, 列) cluster 抽**並列。

**歸因**（`attribute.py`，只對答錯的，程式判，依序取第一個成立的）：該棄答卻硬答 → 誤棄答 → 閉卷（L0）→ 撈錯列（gold 列不在依據）→ 抄錯值（表格值不在算式與引句裡，±1%、×/÷1000、×/÷100；題目給的數不算）→ 算式無效 → 算式選錯（算出來不是正解／需求值）→ 選型錯（需求值對、線徑錯）→ 算錯（L1：算式算出來 ≠ 它填的 value）→ 只錯單位。

**五條規矩**：雜訊底線 L0；盲測基線 L1-fixed；bootstrap 95% 配對差距 + cluster；版本表；漂移探針。

**預期**（事先宣告，只對主檢定下判定）：L0 ≈ .05–.15；L1-struct − L1-fixed ≥ +.10；L1-oracle .7–.8，殘差是抄錯值與算式選錯；L2-struct − L1-struct 在 C2+C3+C4 合併 +.05–.10（可能分不出，半寬約 ±.07–.11）；critical 率 L1 在 .05–.15，oracle 下降一半；棄答題 found 擋八成。

## 4. 結論

**查表接計算這條線，輸贏全在「撈不撈得到正確的那一列」：把對的列直接給模型，答對 .88／.68；靠檢索只有 .28／.22，因為只有四成的題正解列全進得了依據；計算工具（模型寫算式、程式算）幾乎沒救到東西（+.00～+.04），因為算術本來就沒算錯——剩下的錯是規則讀錯（停在中間值、沒分段）與撈錯列，小模型（qwen3）還會在依據不全時選小一級（.17–.27），這是最危險的那種錯。**

## 5. 沒做到的、下次想試的

- **檢索是瓶頸，這次沒修它**：gold 列全在依據只有 .28／.41。一題要兩張表的兩列加一條規則，dense 塞 1,500 字常只撈到一半。下次試：按鏈拆成多次檢索（先查電流表、再查導線表）、表名＋欄名的結構化查詢、12 的 bge-reranker。
- **一列一塊沒有預期那麼值錢**（+.06／+.07，預期 ≥ +.10）：只在 C5 接地（範圍列反查）大贏 +.38／+.46，其他鏈兩種切法都撈不到。
- **工具做的是「算」，錯在「查」與「規則」**：真正的 tool calling（模型呼叫查表函式、分段累進函式）沒做；這次的 L2 是 PoT（模型吐算式、程式求值），救不了停在中間值與單一係數。下次要試的是**把規則寫成函式**讓模型只填參數。
- **棄答**：gpt-oss 在 L2 擋到 .83／.80（接近 11 的八成）；qwen3 只有 .10–.40，給它真的空白的表格它也會硬答（oracle 下 .90 硬答）。要靠程式層判「這格是空的」，不能靠模型。
- 熔線有梯沒出題、斷路器依廠商沒有梯；表只清了 22 張；題目是模板生的（改寫過措辭）；L1 的「算錯」是代理指標（看模型自己的算式），不是真的看它心算；表四○、第 53 條併入照明這些合法替代路徑是用題幹避開的，真實問題不會這麼乾淨。
- 歸因的判定順序（誤棄答先於撈錯列）讓 gpt-oss 的表看起來像「棄答太多」；下次順序改成先看依據有沒有正解。
- **（2026-10-31，17 跑完後補記）16 的乾淨表缺副標**：表二五～二／三／四 的「（導線絕緣物最高容許溫度 60／75／90℃）」清表時沒收，三張表標題一字不差，檢索與模型都分不出哪張是幾度。17 補回後 C1 答對 .08 → .77（兩模型），整體 +.15。16 的 C1 數字與「檢索是瓶頸」有一部分其實是這個資料缺字；另外 17 重跑 gpt-oss 的 L1-struct，答對 .28 → .24（同設定、9 題翻面），16 的 gpt-oss 差距在 .04 以內的都要打折。見 `experiments/17-table-retrieval/README.md`。

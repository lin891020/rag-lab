# 01 切分與檢索：固定長度、照條、小塊固定，哪種找得最準

## 1. 想回答的問題

同一份法規，固定 1000 字切（securag 現用）、照「條」切、跟照條切一樣大小的固定切，哪種讓檢索最準？表格另問：整張一塊、一列一塊、還是攤平照固定長度切？

> **2026-10-30 規則改了，本頁數字還是舊規則的**（審查決議，實驗 15 開工前實作）：固定切的塊沾到條文一個字就算命中 → 改成塊要含該條 ≥ min(100 字, 一半)（`chunkers.span_labels`）；預算規則改成第一塊一定讀（`metrics.hit_at_budget`，跟 10 的 `budget_evidence` 一致）；`run.py` 加 `--questions`／`--out`。重跑後的數字寫在「重算」段，舊數字留著對照。

**檢索**：dense = bge-m3（ollama `/api/embed`）cosine；bm25 = Okapi BM25，字二元組斷詞，k1 1.5、b 0.75；random = 固定種子亂抽 200 次取平均。

**指標**：hit@5 = 前 5 塊有無正解；hit@1000、hit@2000 = 照排名累加字數，整塊放得進預算的塊裡有無正解。結論用 hit@1000：它讓 1 塊 1000 字跟 4 塊 250 字花一樣的閱讀成本比。

**五條評測規矩怎麼套**（檢索是確定性的，三條用等價物）：雜訊底線 = random；盲測基線 = bm25；信賴區間 = 重抽題目 2000 次的 bootstrap 95%，切法之間報配對差距；記版本 = 下表；漂移探針 = 跑完重抽 20 塊直接打 ollama 重算向量，與快取的 cosine 最小值 1.0000（門檻 0.9999）。

## 4. 結論

**固定 1000 字切換成 270 字左右的小塊，1000 字預算內命中率從 .57 升到 .80（+.23，95% 區間 +.07 到 +.40）；但照條切跟同大小的固定切分不出差別（+.00），所以贏的是「塊變小」，不是「照條文邊界」。**

次要的：bge-m3 在 30 題上沒贏過字二元組 BM25，每個切法都分不出；表格整張一塊最好，攤平照 1000 字切最差（dense hit@1000 −.27，分得出），一列一塊沒比整張好。

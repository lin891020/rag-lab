# 25-hosted-tables：換成雲端模型，表格頁怎麼給——文字層、OCR 文字、還是直接給頁圖

## 1. 想回答的問題

同樣 82 題，改用雲端模型（Claude Haiku 5.5、Opus 5.5）答，依據分別給文字層、OCR 讀回的文字、乾淨頁圖、品質差的掃描圖，各答對多少、花多少錢？

## 2. 怎麼做

**為什麼做**：22–24 都用本機小模型答題（qwen3:8b、gpt-oss:20b），一路在處理 OCR 帶來的問題：
- 整張表回純文字。
- 表頭排法。
- 少了表的標題。

實際系統如果用雲端 API 模型、沒有 GPU，這些問題可能根本不存在。而且雲端做法最自然的是不做 OCR，直接把頁圖給模型。所以換模型，看表格頁該怎麼給。

**別人怎麼解的**：
- **20**：Opus 5.5 讀整張表的文字答對 .99，用查表工具 75/75；Haiku 5.5 讀整張表 .99。都是文字依據，沒試過圖。
- **22**：Opus 5.5 把品質差的掃描轉成表格，格子召回 1.00，18 頁花 US$1.27。那是「先轉成文字」，沒讓它直接看圖回答。
- **Tables as Texts or Images**（Deng et al.，ACL 2024 Findings，arXiv 2402.12424）：表格以圖給多模態模型，表現「維持得不錯，有時更好」。
- **ColPali**（arXiv 2407.01449）：直接用頁圖做檢索，在 ViDoRe 上贏 OCR 加文字檢索。那是檢索，不是答題。
- **一個社群評測**（MMLongBench-Doc 30 份、171 題，Claude Sonnet 4.5 答題）：直接給 PDF 看圖 52.0%，比最好的 OCR 管線 59.6% 低，也比較貴；樣本小、非同儕審查。
- **Anthropic 文件**（claude-api skill 的 models／model-migration，2026-11-04 查）：
  - Opus 5.5 是高解析度：長邊 2576 px，每張最多約 4,784 token。
  - 價格（每百萬 token，輸入／輸出）：Opus 5.5 US$4／20、Haiku 5.5 US$0.10／0.50。
  - Haiku 5.5 的圖片上限沒寫，靠實測 token。
- **搜了沒找到**：繁中法規表格、同一批題，「文字層／OCR 文字／頁圖／爛掃描」× 便宜與頂級雲端模型的受控比較。

**計畫**：跑前寫好，Mike 2026-11-04 核准。

**四個條件**（每題的依據都只有正解那張表，照 06／22–24）：

| 條件 | 依據 |
|---|---|
| clean | 文字層的 markdown（04），有標題、表註；跟 24 的 clean 逐位元相同 |
| glm2 | glm-ocr 讀回的文字（06 的轉法），沒有標題；跟 24 的 glm2 逐位元相同 |
| image | 06 的 300 dpi 乾淨頁圖（2481×3508 PNG，原樣送；超過 API 上限的部分由 API 端縮小） |
| image-L2 | 22 最差一級的掃描（150 dpi、歪 1.5°、模糊、雜訊、JPEG q30；1287×1786） |

兩種圖的 sha256 都對 git 裡的紀錄：乾淨頁對 23 讀 06 頁圖時存的雜湊，掃描對 22 的 `results/scan_manifest.json`。

**提示**：
- 06 的提示、system、schema（quote、value、unit）照用，structured outputs 照 20。
- 圖條件只把依據區塊換成「附在這段文字前面的頁圖，共 N 張」，頁圖照頁序放在文字前面。
- 測試鎖住兩件事：依據區塊以外逐字相同；clean、glm2 的提示長度跟 24 送的相同。

**模型**：
- `claude-haiku-5-5`（便宜）、`claude-opus-5-5`（頂級），effort medium（照 20）。
- API 不收 temperature，所以每格跑兩次（`clean`／`clean-2` …），第二次當雜訊底線。
- 2 模型 × 4 條件 × 82 題 × 2 次 = 1,312 次。先 Haiku 全部，再 Opus。
- 每次呼叫都記 token 與花費，失敗、被停的也算。累計超過 US$25 就停（exit 2），停下來問 Mike。
- **被停（拒答、max_tokens）算模型的回答**：留下來、算答錯，不重問；只有網路或伺服器錯誤才在下次重問。
- 接著跑時，提示的 sha256 或圖的 sha256 跟現在的輸入不合的列要重問。score 碰到失敗列、過期列或缺格（例如花到上限停下）就拒絕算分。
- 沒記到的花費：SDK 自己重試（最多 5 次）的中間那幾次，只記最後一次。

**花費估計**（20 的實測：輸入 token 約等於提示字數；Opus 每題輸出約 150–210 token）：約 US$11，約 1 小時。

**主檢定**（跑前宣告；答對要嚴格，82 題，只用第一次；按題與按表 cluster 兩種 bootstrap 的 95% 區間都不含 0，才算分得出）。每個模型各兩個：
1. image − clean：直接給頁圖，跟文字層比。

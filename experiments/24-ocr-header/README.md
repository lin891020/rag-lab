# 24-ocr-header：OCR 讀回的表，把多層表頭攤成一列

## 1. 想回答的問題

glm-ocr 讀回的表，把多層表頭照文字層的規則攤成一列，小模型答對率會不會追上文字層？

## 2. 怎麼做

**為什麼做**：23 之後，乾淨頁經 glm-ocr（提示尾加換行，下稱 glm2）讀回來，答對率仍比文字層（clean）低 .06（兩個模型都是，分不出）。用 23 的結果比對 clean 答對、glm2 答錯的題（沒有打模型）：
- 在 glm2 有回表格的表裡，**格子跟文字層一模一樣**，差在表頭。
- 文字層的多層表頭攤成一列，例如「同一導線管或電纜內之載流導線數／3以下／安培容量（A）」。
- glm2 的 HTML 經 06 的轉法，表頭留成三列，第二、三列落在 `|---|` 下面，看起來像資料列。

17 張表裡，表頭超過一列的有 8 張，共 42 題：

| 模型 | clean 答對 | glm2 答對 | 兩邊答案相同 |
|---|---|---|---|
| qwen3 | 32 | 29 | 31/42 |
| gpt-oss | 38 | 36 | 34/42 |

其餘 40 題的差距，主要是 表四○ 回純文字（23：縮圖救不回）和 表九三～一 的表註。

**別人怎麼解的**：
- **04**（`experiments/04-table-lookup/tables.py` 的 `column_names`）：文字層就是這樣攤平的——每欄由上往下取表頭格，跟上一段相同就跳過，用「／」接起來。這次照抄。
- **17／18**：
  - 17：qwen3 讀整張表時，表頭只寫一次就會取錯欄。
  - 18：改成每格帶欄名（kv），讀錯欄變少，但答對率分不出。
  - 這次不試「每格帶欄名」，只把表頭排成文字層那樣。
- **docling-core 的 `export_to_dataframe`**：表頭列數到第一個沒有表頭格的列，每欄把各列的表頭文字接成一個欄名。R 的 `unheadr::mash_colnames` 也一樣，分隔符號可以自己選。
- **文獻**：
  - TABQAWORLD（arXiv 2604.03393）：每列重複欄名的格式略好。
  - OHD（arXiv 2602.01969）、ASTRA（ACL 2026）：主張單純攤平會丟掉階層，改用樹。
  - TableEval（arXiv 2506.03949）：有合併格時，HTML 比 markdown 高約 2 分。
  - OfficeQA Pro（arXiv 2603.08655）：哪種格式好，因模型而異。
- **GLM-OCR 官方 SDK**（arXiv 2603.10910）：先切版面區域再分區辨識，表格輸出 markdown；沒寫多層表頭怎麼處理。
- **搜了沒找到**：同一批 OCR 表格，「多列表頭的 markdown」對上「攤成一列」，用小模型答題的受控比較。

**計畫**：跑前寫好，Mike 2026-11-04 核准。

**不呼叫 glm-ocr**：用的是 23 存下的 glm2-s100 原始回覆（06 的 300 dpi 頁圖；23 驗過跟 22 的 glm2-L0 17/17 逐字相同，22 驗過跟 06 逐字相同）。`build_corpus.py` 每頁轉 markdown 後用換行接起來，照 23 的做法。每份回覆的 sha256 記在 `corpus/sources.json`，`run.py` 開跑前會再比一次。

**三個條件**（`prompts.py`）：

| 條件 | 依據 |
|---|---|
| clean | 04 的 markdown（pdfplumber 文字層），盲測基線，同一晚重跑 |
| glm2 | 06 的轉法；跟 23 的 glm2-s100 逐位元相同（測試） |
| glm2-flat | 同一份回覆，`<thead>` 超過一列時攤成一列（`ocr.py` 的 `flatten`，04 的規則） |

**攤平**：
- 表頭列以 HTML 的 `<thead>` 為準，而且 thead 裡要有一格橫跨好幾欄（colspan > 1）才算多層表頭。表五六 第 2 頁是接續頁，glm-ocr 把前兩列資料（26 - 30、31 - 40）包進 thead，沒有跨欄格，所以不動（見下面的跑前審查）。
- 表頭只有一列、或回純文字的表，攤平前後逐位元相同（測試）。所以 glm2-flat 只改到 8 張表、42 題的提示。
- 攤平前後的表頭，以及跟文字層表頭的對照，在 `corpus/headers.md`。跑前就知道（逐格比，NFKC、去空白）：
  - 表二五～二／四／五／七：攤平後跟文字層相同。
  - 表九三～二、表五六、表八八～二：只差 OCR 的字（装、额；表五六 是「注」加上上標殘留的「^{」）。表五六 的文字層自己也有「l2kW」「l.75」（1 讀成 l）。
  - 表八六～三：文字層自己的表頭就是壞的。

**答題層**（`run.py`、`score.py`、`report.py`，照 23）：
- 06 的 82 題、提示、schema、模型設定都照用：qwen3 think 關、gpt-oss think low、temperature 0、seed 0。
- 3 條件 × 2 模型 × 82 題 = 492 次，加漂移探針。
- clean 與 glm2 的提示跟 23 送的逐字相同（測試比對每題的提示長度，語料逐位元相同），所以 23 的那兩格可以當雜訊底線。

**主檢定**（跑前宣告；答對要嚴格，82 題；按題與按表 cluster 兩種 bootstrap 的 95% 區間都不含 0，才算分得出）：glm2-flat − glm2，兩個模型各一個。

**描述、不下判定**（`posthoc24.py`）：
- 雜訊底線：clean、glm2 對 23 同一份提示，回覆逐字相同幾題、答案相同幾題。
- 陰性對照：提示沒變的 40 題，glm2 對 glm2-flat。
- 跟 clean 同答（value 相同）的題數，分多層表頭 42 題／其他 40 題。
- 按表答對、逐題翻面、clean 對但 glm2-flat 錯的題。

**預期**（寫在計畫裡，核准時就定了）：
- glm2-flat − glm2：qwen3 +.02～+.05、gpt-oss +.00～+.03，都分不出。會變的只有 42 題，這 42 題裡 clean 也只比 glm2 多對 3 題、2 題。
- 多層表頭 42 題跟 clean 同答：qwen3 31 → ≥ 36、gpt-oss 34 → ≥ 37。
- qwen3 陰性對照 40/40 相同；雜訊底線 qwen3 82/82 相同。
- clean − glm2-flat ≤ +.04：剩下的是 表四○、表九二 回純文字和表註。

**跑前審查**（另一個 agent 讀程式、離線跑，沒打模型）：
- **擋下一個會讓條件不純的錯**：表五六 第 2 頁的 thead 其實是兩列資料，原本的攤平會把它們併成一列（「26 - 30／31 - 40 … 24／22」）。改成 thead 要有跨欄格才攤平；測試鎖住：只有 8 張表的第 1 頁會變，而且每頁拿掉的正好是 thead 那幾列。
- 其他補強：
  - `run.py` 開跑前，把語料跟重新建一次的結果逐字比，舊檔不能混進來。
  - 接著跑時，提示長度跟現在的語料不合的列要重問。
  - `score.py` 有失敗的呼叫或過期的列就拒絕算分。
  - posthoc 並列這次與 23 的機器、ollama 版本、模型 digest。
  - 兩個都解析不了的回覆不算「同答」。
  - clean 語料跟 23 逐位元相同（測試）。
- 審查也確認：
  - glm2 跟 23 逐位元相同；三個條件的提示除了依據區塊都一樣；glm2-flat 只改 42 題的提示。
  - 主檢定方向正確；posthoc 的翻面方向與陰性對照的題組正確。
  - 上面那張 32／29／31、38／36／34 的表，用 posthoc 的函式從 23 的列重算得到同樣的數。

## 4. 結論

**把 OCR 表的多層表頭攤成一列，沒有讓答對率追上文字層。qwen3 在攤平後跟文字層一字不差的 4 張寬表，多對 3 題，正好是取錯欄的那幾題；但在另外 4 張表少對 4 題（其中 2 題數字對、單位寫錯），淨 −.01。gpt-oss +.00。跟文字層的 .06 差距還在，剩下的主要是 表四○ 回純文字和 表九三～一 少了標題。**

## 5. 沒做到的、下次想試的

- **qwen3 對表頭的小改動很敏感**：同一列、表頭只差一個字，就換一欄取值。攤平修好了它在寬表取錯欄的題，卻在別的表弄出新的錯，淨效果是 0。這跟 18 的結論同一個方向：小模型的查表交給程式（19 的查表工具），不要靠換排版。
- **表的標題**：glm-ocr 的 Table Recognition 只回表格，不回標題。表九三～一 少了標題後，gpt-oss 3 題改去用表註算。補回標題有沒有用、是不是原因，沒拆。做法可以是用 Text Recognition 再讀一次頁首，或照 GLM-OCR 官方 SDK 先切版面區域。
- **表四○ 回純文字**：23 試過縮圖救不回。還沒試換提示重讀。
- **單位**：表八六～三 攤平後第一欄的欄名把「(A)」和「(kA)」接在一起，qwen3 有 2 題取了「A」。這是 glm-ocr 把斜線分隔的角落格讀成一格，攤平又把它放進欄名。
- **題太少**：會變的只有 42 題；qwen3 兩個方向的翻面加起來 9 題，量不出小差別。

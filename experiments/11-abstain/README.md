# 11 找不到要說找不到：依據裡沒答案時，本機模型多常硬答

## 1. 想回答的問題

依據裡沒有答案的時候，qwen3:8b 與 gpt-oss:20b 多常還是給一個答案？在提示裡給它「沒有就說沒有」的選項救回多少，有答案的題又掉多少？事後用程式驗「它引的那句在不在依據裡」還能擋掉多少硬答、誤擋多少對的？

## 2. 怎麼做

**別人怎麼解的**：
- **RGB**（AAAI 2024，arXiv 2309.01431）四個測試床之一是 negative rejection：只給雜訊文件，看模型會不會說「資訊不足」；最好的模型英文 45%、中文 43%。判定用字串比對加 ChatGPT 當裁判 → 這裡的 other-doc 組就是它的中文版，判定全用程式（schema 有 `found` 欄），不用裁判模型。
- **UAEval4RAG**（arXiv 2412.12300）對每個知識庫自動生成答不了的問題，報 unanswerable ratio 與 acceptable ratio；發現答對率最高的設定常常棄答率最低——是取捨 → 有答案組與無答案組都報配對差距。
- **AbstentionBench**（NeurIPS 2025，arXiv 2506.09038）：棄答是沒解的題，模型變大沒用，推理微調反而掉 24%；寫得好的 system prompt 有幫助但沒根治 → P1 只改提示，預期救回一部分。
- **VERICITE**（BioNLP 2026）：就算給 oracle 檢索，引用的忠實度也只有 27–41% 段落級撐得住，結論是生成端自己會亂引、要有驗證步；實務做法（ragground 等）是要求逐字引句、程式驗引句在不在來源裡 → 02 起每題都要模型附 quote，從沒驗過；這次加一個不叫模型的濾網。
- **本機**：09 `run_read.oracle_window`、`budget_evidence`、10 `score.judge`（新尺）；09 的 160 題。09 的旁證：依據不含正解時 qwen3 93%、gpt-oss 85% 還是給了答案。

**語料與題庫**：讀 09 的 30 份公報、160 題（數字 109、條號 18、哪一份 33）與 10 的 ocrrows 路線，不複製。

**依據五種**（`run_read.py`，每題每種各做一次；`prompts.EVIDENCE`）：

| 依據 | 怎麼做 | 有答案？ | 可用題數 |
|---|---|---|---|
| gold | 09 的 oracle 窗：quote 前後 1,000 字 | 有 | 160 |
| same-doc | 同一份文件、不含 quote 的 1,000 字窗：從 quote 往後跳 1,500 字取，取不到就從頭、再不行就緊接著 quote 之後 | 無（對的法規、錯的地方，最難的誘餌） | 118（14 份太短組不出、28 題 leak） |
| other-doc | 10 的 full 索引裡 dense 排最前的**別份**文件的塊，截到 1,000 字 | 無（像的法規） | 138（2 題沒有別份、20 題 leak） |
| none | 不給依據 | 無 | 160 |
| real | 10 的 full 條件：ocrrows／article-cn+pre／前綴，dense 前幾塊塞 1,000 字 | 混合：`has_gold` 132 有、28 無 | 160 |

**leak**（`run_read.leak`）：號稱沒答案的窗其實有答案——數字題看正解數字（阿拉伯與中文寫法、含「萬」的兩種寫法）緊接著題目的單位出現；條號題看每個正解條號都以「第N條」出現；哪一份題看法規名出現。leak 的題從統計排除、數量照報。哪一份題在 same-doc 幾乎都 leak（同一份文件到處是它的名字），所以 same-doc 組主要是數字題與條號題。

**提示兩種**（`prompts.py`）：
- **P0**：09 的提示逐字相同（`tests/test_prompts.py` 比對），schema 逼它填數字，沒有棄答的路。棄答判定（事後）：value 是 0／null、articles 空、law 空、或 quote 含「無／沒有／未規定／找不到／不適用／無法」。
- **P1**：schema 第一個鍵加 `found`（bool），規則加一句「依據裡找不到答案就 found 填 false，其餘欄位填空或 0，不要用你自己知道的補」。

**程式濾網**（`score.grounded`，兩種提示的輸出都過一次，不叫模型）：quote 去空白、NFKC 後至少 4 字且出現在依據裡才算有根據；有答案但沒根據 → 改判棄答。

**指標**（`score.py`）：
- 無答案組（same-doc、other-doc、none、real 的沒正解半邊）：**硬答率**（給了答案）、沒根據的對（答對但依據裡沒有）、濾網後硬答率。
- 有答案組（gold、real 的有正解半邊）：答題率、答對率（10 的嚴格／寬鬆尺）、濾網後答對率（誤擋的成本）、引句有根據的比例。
- bootstrap 95%；P1 − P0 配對差距；濾網後 − 濾網前；按題型。

**規模**：160 題 × 5 依據 × 2 提示 × 2 模型 = 3,200 次，10 跑完接著跑（可續跑）。模型設定同 09：qwen3:8b `think:false`、gpt-oss:20b `think:"low"`、temperature 0、seed 0；漂移每格重打 2 題。

**五條規矩**：雜訊底線 none；盲測基線 P0（09 的提示原樣）；bootstrap 95% + 配對差距；版本表（下）；漂移探針。

**預期**（事先宣告）：P0 硬答率 .85–.95；P1 把 other-doc／none 壓到 .3–.5、same-doc 最難壓；P1 在 gold 組掉 .03–.08；濾網再擋掉硬答的三到五成、誤擋有答案的 .05–.10。

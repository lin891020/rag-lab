# 真資料來了怎麼做：01–10 的結論整理成一條流程

寫給拿到一批新文件、要讓本機模型回答問題的人。每一步只寫「做什麼、為什麼、數字在哪」；數字全部來自 `experiments/` 各 README 第 3 節，區間是 bootstrap 95%。目前所有資料都是 PDF；非 PDF（Word／Excel）還沒量過。
整理日期 2026-10-29；10 的數字跑完補。

## 0. 先想清楚要量什麼，再動手

- **先出題，再做 pipeline。** 每題帶一句原文（quote）當正解的錨：檢索命中 = 撈回來的塊含這句；答題對錯用程式判（數字＋單位、條號集合、法規名），不靠人看（09）。
- **題數 160 起跳。** 40–80 題的區間寬到 ±.09，大多數修法分不出（01、07、08 都卡在這）；160 題能分 ±.07（09）。
- **五條規矩每次都要**：雜訊底線（random／閉卷）、盲測基線（什麼都不改先跑一次）、區間與配對差距、版本表、漂移探針。沒有這五條的數字不要信，包括自己的。
- 題庫自己出的要有人抽查；人沒空就讓一個沒看過題目的 agent 從頁面截圖獨立作答再比對（09：15/15）。

## 1. 體檢：進模型之前先用程式看一眼

跑 `experiments/09-messy-real/doc_health.py <資料夾>`（08 的加兩欄），每份一列。看這幾欄決定走哪條路：

| 欄 | 看到什麼 | 代表 | 怎麼辦 |
|---|---|---|---|
| `text_pages < pages` | 有頁沒文字層 | 掃描頁 | 那幾頁走 OCR（第 2 步） |
| `garbage_share ≥ .2` | 文字層是 `(cid:N)` | 嵌入字型沒對照表，三個抽字器都救不回 | 當掃描頁走 OCR（09：29 頁有 28 頁是這樣，08 的體檢會說「有文字」） |
| `rotated_pages > 0` | 橫式附表 | pdfplumber 會倒著讀，pypdf／PyMuPDF 正常 | 表格路線跳過這些頁 |
| `two_column_pages` | 兩欄排版 | pdfplumber 會把兩欄交錯，條號黏掉，一條一塊 −.80 | 用 pypdf 抽，或先切欄（08） |
| `table_pages` | lines 策略找得到表 | 有框線表 | 走表格路線（第 2 步） |
| 頁首頁尾重複行 | 多 13 字／頁 | 對檢索命中無害（08）；但頁碼會騙過跨頁接續規則、多一行標頭會讓 1,000 字塊超出 1,000 字預算（09） | 看第 4 步的預算 |

## 2. 抽字：三條路線，按體檢結果分頁走

- **文字頁**：pypdf 抽字（01 起一直是基線）。
- **掃描頁／亂碼頁**：glm-ocr 0.9B，300 dpi 頁圖，提示用「Text Recognition:」**結尾加換行**；跟原本文字層答對率分不出（06：.73 vs .79、.88 vs .93）。提示照抄會掉 .10，寬表它只回純文字。Apple Vision 掉 .35–.43、tesseract chi_tra 等於沒讀，不要用（06）。只 OCR 體檢標出的頁，10 秒/頁，結果要快取。
- **表格頁**：pdfplumber lines 策略拿格子。餵模型時轉 **markdown 或逐列鍵值**，比攤平文字多對一截（03：qwen3 .67 → .79／.84、gpt-oss .73 → .95／.87）；HTML 沒幫助（03）。範圍列展開、只餵問到的列都救不了剩下的錯（04，四個區間含 0）。
- **跨頁表**：前表到頁底＋後表在頁頂＋欄界對齊 → 接回（05：4/4 真跨頁、108 鄰表 0 誤接）；但公報每頁表下有頁碼，05 的「表下沒字」檢查會失效，改看「列首有沒有條號」（09 `extract.compare_rows`）。
- **修正案的三欄對照表**（修正條文／現行條文／說明）：重建成「一條一筆、每格前標欄名」。對檢索命中沒差（±.02），對閱讀有差：沒標欄名時兩個模型都抄到現行欄（09 汞 0.4 vs 修正後 0.3）。
- **無框線表**：text 策略會把欄黏成一格（08：gpt-oss −.11）；x 座標當欄線的修法沒做過。
- **拿得到原始格式（法規系統 HTML、附件）時**：當補充、不當替代。HTML 少了令文、附表、標題那一層（32/87 題答案不在裡面，答對 −.24）；加附件後跟 PDF 打平；兩邊都有答案的題分不出——PDF 抽字修好之後，損失在內容不全不在格式（14）。

## 3. 切塊：小塊贏，結構只在找得到的時候有用

- **塊要小**：1,000 字固定切換成約 270 字，1,000 字預算內命中 .57 → .80（01）。贏的是「小」，不是「照條」：照條切跟同大小固定切分不出。
- **照條切有前提**：條號格式要對得上。01 的規則要「第 14 條」獨立成行，公報寫「第十四條之一　漁船…」中文數字同行，160 題一條都切不出（09）。中文數字規則加上去 +.55；fixed-1000 是保底，在公報上跟最好的切法打平（.75 vs .78）。
- **條文之前的字不要丟**：公告主旨與總說明寫著「這次修正哪幾條」，條文裡沒有；留成塊 +.23（09）。哪些是雜訊要看問題問什麼。
- **沒有「條」的文件**（要點用「一、二、」，附表公告整份是表）：09 有 10 份切不出，只能靠 fixed-1000；專用切法還沒做。
- **一條一塊之後別再加花招**：標題鏈前綴 0、脈絡句 +.03、父子 0、dense＋BM25 混合 −.05～+.03，區間全含 0；頁級切塊 −.28 輸在塞不進預算（07）。
- **《法規名》前綴**的真正用處在閱讀：30 份一起索引時「哪一份規定了 X」的題，沒前綴 .24、有 .85（09，跟前言塊一起量的，10 拆開）。
- **沒有「條」的文件（要點、附表）**：固定切 300 字就夠（預算內有正解比 1,000 字 +.20）；照「一、二、」切成一點一塊跟 300 字分不出；附表一列一塊閱讀 +.15 碰邊。前綴照樣要帶（13）。

## 4. 檢索與預算

- dense（bge-m3）跟 bm25 字二元組在法規與公報上幾乎同分，random 是 .00–.01（01、09）。
- **預算跟塊大小會耦合**：hit@1000 要整塊放得進 1,000 字，1,000 字的塊多一行標頭就出局（09：34–52 題）。要嘛塊切 900、要嘛另報 hit@2000；這條還沒解。
- 30 份放一起，真的撈錯份的只有 9/160 題；撈錯份不是主要損失（09）。
- **第一階段 dense 之後接 cross-encoder 重排**（bge-reranker-v2-m3，前 50）：預算內有正解 +.11（一條一塊）／+.21（固定切），答對率 +.05／+.06，一題 3 秒（12）。RRF 合併、Qwen3 生成式重排、LLM 列表式重排都不值：±.03、37 秒、或在長塊上變差 −.14（12）。

## 5. 餵模型與評分

- **給依據、要一個數字時，格式不是問題**：提示詞拜託、json-mode、schema 三種輸出一模一樣，格式錯誤 0（02）。錯都在讀表。
- **模型設定**：qwen3:8b `think:false`；gpt-oss:20b 開 schema 要 `think:"low"`（ollama 0.40.2 無視 `think:false`）；temperature 0、seed 0；每格重打 2 題看漂移（09：19/20 同）。
- **分開檢索損失與閱讀損失**：加一個 oracle 條件（直接餵含正解的 1,000 字），上限 .87／.83（10 的新尺）；依據含正解時答對 .88／.78，不含時 .18–.27（09）。
- **評分尺**：數字對且單位對是嚴格分；單位同義（個月／月、人／名）要收進別名，單位空白另算寬鬆分（gpt-oss 常不填單位：嚴格 .83、寬鬆 .93，10）。中文數字沒有比阿拉伯數字難；阿拉伯數字題差是因為它們都在附表裡、攤平後數字對不回列（10）。
- **找不到要說找不到**：schema 加一個 `found` 布林、規則加一句「找不到就填 false」，依據裡沒答案時硬答從 .91／.86 降到 .09／.11（有依據可看時），有答案的題不掉（11）。但**沒有依據時模型照答**（.66／.94）：檢索撈不到就不要叫模型，程式層擋。再掛兩層程式濾網：引句要在依據裡（擋 gpt-oss 編的引句，九成）、引句要含答的數字（才擋得到 qwen3 抄真句答假數，.66 → .23）；否則改判棄答。誤擋有答案的 .04–.08（11）。
- **兩個模型都跑**：很多結論只對一個模型成立（03 的 markdown vs kv、08 的無框線），一個模型的數字不要推到另一個。

## 6. 修法的順序（09 在 30 份公報量的，10 拆開量後更新）

| 修法 | 檢索命中 | 答對率 | 什麼時候才值得 |
|---|---|---|---|
| 條號規則對上文件的寫法（或退回 fixed-1000） | +.55（對壞掉的一條一塊；對 fixed −.03） | fixed 比不改的 +.43／+.39；一條一塊比 fixed 只 +.04／+.06，區間含 0（10） | 永遠先做；規則對不上就退回 fixed-1000，不急著寫規則 |
| 條文之前的字留成塊 | +.23 | 關掉 −.21／−.17；條號題 .56 → .17（10） | 有「這次改了哪裡」這類題 |
| 掃描／亂碼頁走 OCR | +.11 | +.07／+.08，加一個關一個都分得出（10） | 體檢看到就做，20 題從 0 變有 |
| 對照表一條一筆標欄名 | ±.02 | ±.00（關掉反而 +.01／+.03，10） | 文件有修正／現行兩欄 |
| 《法規名》前綴 | +.01（hit@5 +.04） | +.17／+.16，幾乎全是「哪一份」題（.21 → .94）；數字題 +.12（10） | 多份一起索引、問「哪一份」 |

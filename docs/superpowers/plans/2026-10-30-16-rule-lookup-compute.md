## 1. 使用者要的是什麼（原話）

## 3. 別人怎麼解的（查過的）

- **AECBench**（arXiv 2509.18776，AEC 領域 4,800 題、五個認知層級）：模型最弱的是「讀規範裡的表」與「計算」；沒有做 RAG 對閉卷的比較 → 16 補這個。
- **錯誤歸因**：SEER（arXiv 2310.06675）對 TAT-QA／FinQA 的分析——取值錯 63%／76%、算式選錯 30%／45%、執行錯 0%／4%。→ 工具只救執行錯，16 把四類分開數，不然 L2 的收益會被誤判。
- **程式幫算（PoT）**：Program-of-Thought 是 FinQA／TAT-QA 的標準基線（MATATA, arXiv 2411.18915 的表）；小模型＋生成程式（arXiv 2512.13323）TAT-QA 精確率 60 → 71。→ L2 用「模型吐算式、程式算」有據。
- **找欄位再精算**（arXiv 2601.18012）：報精確與容差兩種指標、記 schema 合規、說「什麼時候提示夠、什麼時候要演算法骨架」。→ 兩把尺（1% 容差、梯上的級）並列。
- **SciTaRC**（arXiv 2603.08910）：寫程式算在原始表上脆、自然語言推理敗在讀表與算；GPT-5 也只 76.8%。
- **本機**：03（表格 markdown／kv 比攤平 +.12～+.22；寬表與範圍列是殘留錯）、04（整張表餵進去 .79／.91，列召回 .95，錯在抄到註解與讀錯欄；`corpus/tables.json` 17 張乾淨表）、11（`found`、兩層濾網）、10（尺、`budget_evidence`）、15（`merge.cluster_diff_ci`、獨立 agent 出題與核題的流程）、01 的 `parse_articles`／`article_chunks`／`table_row_chunks`；梯級評分語意（match／acceptable／error／critical）。
- **搜了沒找到**：針對電工法規導線選型的 LLM 評測（NEC 310.16 之類只有參考頁與廠商宣稱）；台灣用電規則的任何 LLM 評測。

**一個問題**：給一個負載情境，L0／L1／L2 各能答對多少、選小多少、該棄答時棄答多少；錯的落在撈錯列、抄錯值、算式選錯、算錯哪一步。

### 4.4 尺與歸因（`score.py`、`attribute.py`）
- 數字題：相對誤差 ≤ 1% match，否則 error；選型題：梯級 match／acceptable（大一級）／error（大兩級以上）／**critical（小於）**；棄答題：`found:false` 對、硬答錯；非棄答題硬答率照報。單位嚴格／寬鬆兩把尺（10）。
- 歸因（只對答錯的，程式判）：gold 列不在依據 → 撈錯列；算式或引句裡的數不在中間值裡 → 抄錯值；數字都對但 value 不等於正解且 L2 → 算式選錯；L1 的 value ≠ 模型自己算式的值 → 算錯；單位；該棄答沒棄答。
- 指標：各條件答對率、critical 率、棄答對率、硬答率、`expr_ok`；gold 列在依據內的比例（(表號, 列鍵) span 標籤，檢索損失）；**主檢定**（每模型 6 個，見第 2 節）用全 160 或 C2+C3+C4 合併；鏈內差距只描述；bootstrap 2000 次 seed 0、以鏈分層、鏈內按 (表, 列) cluster 抽，與按題抽並列。

**五條規矩**：雜訊底線 L0；盲測基線 L1-fixed（08 的保底）；bootstrap 95% 配對差距 + cluster；版本表；漂移探針。

**預期**（事先宣告，只對主檢定下判定）：L0 ≈ .05–.15；L1-struct − L1-fixed ≥ +.10（一列一塊 vs 固定切，03／04 的方向；兩邊同一份文字，差的只是切法）；L1-oracle .7–.8，殘差是抄錯值與算式選錯；L2-struct − L1-struct 在 C2+C3+C4 合併 +.05–.10（可能分不出，半寬約 ±.07–.11）、全 160 更小；critical 率 L1 在 .05–.15，oracle 下降一半；棄答題 found 擋八成（11）。

# 實驗 18：整張表每格帶欄名——qwen3 讀錯欄會不會消失 — 計畫

日期 2026-10-31，mini。17 的程式、題庫、語料照用（複製進 18，不共用）。語料仍是公開的《用戶用電設備裝置規則》。

## Context

17 的發現：「先找表、整張給」（cards）讓正解列進得來，但 qwen3 拿到整張 markdown 表會讀錯欄——例「75℃、2.0 mm 單線、管內 8 條」：一列一塊（每個值前寫欄名）答 16 對，整張表（欄名只在表頭一次）找到 2.0 那列卻取第一欄「3以下」的 23。歸因 qwen3「算式選錯」struct@3000 5 → cards 22。gpt-oss 不受影響（cards − struct@3000 +.11）。這個「讀錯欄」只是看例子推的，HANDOFF 列在「還沒驗證」。另外 gpt-oss 同設定重跑會飄（17 量到 127/160 同答、答對 −.04），那個 +.11 站不站得住也還不知道。

## 1. 使用者要的是什麼（原話）

- 我：「先做『整張表帶欄名』…『規則寫成程式』照原定 11/2 之後」、「順便 gpt-oss 在『先找表、整張給』那格再跑一次…才知道這個 +.11 站不站得住」→ Mike：「好」。
- 成功的樣子：一句話回答「整張表改成每格帶欄名，qwen3 答對升多少、讀錯欄少多少；gpt-oss 會不會反而掉；gpt-oss 自己重跑飄多少」。

## 2. 可能會錯在哪（每條有防呆）

| 會錯的地方 | 為什麼 | 怎麼防 |
|---|---|---|
| **kv 比較長，同預算塞進的列變少**，贏輸混著「格式」與「內容」 | 03 的全欄名 kv 是 markdown 的 2–3 倍；表二五～二 從 1,057 → 3,248 字，3,000 放不下 | 主格 **cards-kv＝同一批內容**：照 cards 原樣（markdown 長度、3,000 預算）選出要放哪些表、哪幾列，選好之後才把乾淨表改寫成 kv；內容一字不差、只差寫法。同預算的代價另算一格 cards-kv@3000，只跑檢索軌（正解列全進率），不進閱讀軌 |
| **全欄名 kv 太長**（「同一導線管或電纜內之載流導線數／3以下／安培容量（A）=19」） | 會撐爆 num_ctx 8192、也稀釋 | 短欄名：表頭照舊寫一次全名，每列只寫「同組欄名裡不一樣的那段」（`3以下=19；4=17；5-6=15；7-9=13`）；撞名（表二五八～三 兩組都有 380）就兩個都補組名。實測 22 張乾淨表合計 11,321 → 19,149 字（×1.69），最長單表 表五六 3,381；17 最長提示 5,122 字兩模型都沒截（done_reason 照記）。**另記 `prompt_eval_count`**，跟字數比對，有截斷就看得出來 |
| **短欄名規則是看著這幾張表定的** | 等於針對題庫調 | 規則寫死、通用（只看欄名的「／」分段），測試只驗規則本身；README 寫明 |
| **87 張原始表沒有欄結構** | 它們是 PDF 文字，沒有乾淨欄名 | 原始表照原文，不改；README 寫明 kv 只動 22 張乾淨表（C1–C5 的正解都在乾淨表裡） |
| **「讀錯欄」量不到** | 17 的歸因只有「抄錯值」「算式選錯」，沒分欄錯／列錯 | 歸因加一個描述用欄位（不改原本分類順序）：答錯而且依據裡有正解列時，模型寫的數字＝正解列的別欄 → `wrong_column`；＝正解欄的別列 → `wrong_row`；比對 ±1 %。測試用 17 那題（23 vs 16）當例子 |
| **gpt-oss 會反而掉** | 03：gpt-oss markdown .95 > kv .87（+.09 分得出） | 事先寫進預期；兩模型分開報 |
| **qwen3 寬表本來就弱，換格式救不了** | 03：表二五～二／四／五（7 欄 21 列）qwen3 任何格式 .2–.8 | 事先寫進預期；另報 C1–C3 拆鏈與「正解列全進時的答對率」 |
| **沿用 17 的 qwen3 cards 結果飄掉** | 模型或程式變了 | 重打 10 題當探針，要 10/10 同答（17 量過 qwen3 一字不差）；不到就整格重跑 |
| **gpt-oss 重跑雜訊只量一次** | 一次重跑只是一個樣本 | 誠實寫：這是第二次重跑（第一次在 struct@1500），兩格各一次；不推廣到其他實驗 |

## 3. 別人怎麼解的（查過的）

- **本機 03-table-format**（同一份法規表、82 題）：kv − markdown qwen3 +.05（kv .84 vs md .79，分不出）、gpt-oss −.09（分得出，markdown 好）；寬表 qwen3 什麼格式都弱。→ 預期 qwen3 小升、gpt-oss 可能掉。03 的 kv 用全欄名、是 markdown 的 2.2 倍字數（flat 的 3.7 倍）。
- **Improving Agents〈Which table format do LLMs understand best〉（2025，GPT-4.1 mini/nano，11 種格式、1,000 列員工表）**：Markdown-KV 60.7% 最高、XML 56.0、CSV 44.3、markdown 表中段；作者說換模型換表可能翻盤。HN 討論的解釋是「一般表格讓模型把值對到錯的欄名」——正是我們要驗的，但沒人做過對照。
- **Sui et al.〈Table Meets LLM〉（WSDM 2024）**：格式、內容順序、分隔記號都會影響；HTML＋格式說明在 GPT-3.5/4 上最好。**TableEval（2506.03949）**：HTML／LaTeX 比 markdown 高約 2 點。→ 格式排名看模型與任務，不能抄結論，要在本機兩個模型上量。
- **搜了沒找到**：「找到整張表之後，只改寫法、內容固定」的受控比較；也沒找到短欄名（只寫分組裡不同那段）的做法，這是我們自己定的。

## 4. 設計

**一個問題**：cards 撈進來的整張乾淨表，從 markdown 改寫成每格帶欄名（短欄名 kv），內容不變，答對率與「讀錯欄」各變多少。

### 格

| 格 | 依據 | 閱讀軌 |
|---|---|---|
| cards | 17 原樣 | qwen3 沿用 17（探針 10 題）；**gpt-oss 整格重跑**（＝新基線＋雜訊量測） |
| cards-kv | cards 選定的同一批表與列，乾淨表改寫成短欄名 kv | 兩模型新跑 |
| cards-kv@3000 | 卡片排名同 cards，但用 kv 長度塞 3,000 | 只跑檢索軌 |

模型、提示、尺照 17（qwen3:8b、gpt-oss:20b；temperature 0、seed 0、num_ctx 8192、num_predict 1024；L1 輸出 `{found, quote, expression, value, unit}`）。

**主檢定**（事先宣告，答對嚴格、130 題有答案、配對 bootstrap 95%＋cluster，照 17）：
1. cards-kv − cards，qwen3
2. cards-kv − cards，gpt-oss（基線用 18 重跑的 cards）

**描述（不下判定）**：C1–C3／C4–C5 拆鏈；正解列全進時的答對率；`wrong_column`／`wrong_row` 次數；gpt-oss cards 兩份（17 vs 18）同答比例、對錯翻面題數、答對差距與區間，並用兩份各自重算 17 的檢定 1（cards − struct@3000）。

**五條規矩**：雜訊底線＝gpt-oss 這次重跑＋qwen3 探針；盲測基線 cards；bootstrap 區間；版本表（digest，須與 17 同）；漂移探針（qwen3 沿用 10 題；新格每格 2 題重打）。

**預期**（事先宣告）：qwen3 cards-kv − cards +.05～+.10，可能分不出，主要在 C1–C3；qwen3 `wrong_column` 至少減半；gpt-oss −.05～+.03，分不出；gpt-oss cards 重跑同答 ~80%、答對差距 ≤ .05；cards-kv@3000 正解列全進率比 cards 低 .05 以上。

**呼叫數**：qwen3 160＋10 探針；gpt-oss cards-kv 160＋cards 160 ＝ 490 次。照 17 的每次 12–21 秒，約 2–2.5 小時。先 qwen3、再 gpt-oss（只換一次模型）。

## 6. 順序

1. 複製 17 的程式；先寫測試（短欄名、cards-kv 標籤一致、wrong_column），看它失敗，再寫程式。
2. 檢索軌：cards、cards-kv、cards-kv@3000（嵌入全走快取；卡片沒變，不應有新嵌入）；確認 cards-kv 與 cards 的正解列命中逐題相同。
3. 跑前**獨立審查**（另一個 agent 審 kv 改寫、命中判定、沿用 17 raw、wrong_column 判定）；全套測試 exit 0（deselect 兩檔）。
4. `chain18.sh` 背景跑，等候器盯 log。
5. 跑完：README 五節、17 README 第 5 節補一句指到 18、根 README 一列、playbook §7 一條、HANDOFF、memory（若 gpt-oss 雜訊量到新東西就更新 `gpt-oss-rerun-noise`）、commit、push；回報 Mike 一句話。

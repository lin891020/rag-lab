# 雲端模型版的做法清單：01–27 的結論，換成用 Claude API 答題時怎麼做

寫給要用雲端 LLM API（不跑本機模型）做「查法規條文與附表、回一個數」系統的人。
本機小模型版的流程在 [2026-10-29-real-data-playbook.md](2026-10-29-real-data-playbook.md)；這頁只寫換成雲端模型後**還要做的、不用做的、要另外擋的**。
整理日期 2026-11-04。模型是 Claude Haiku 5.5 與 Opus 5.5（effort medium，structured outputs）。

每條後面標來源：**〔雲〕** 是在雲端模型上量過的（20、22、25–27）；**〔本〕** 是只在 qwen3:8b／gpt-oss:20b 上量過、這裡推測仍成立的，上線前要補量。

## 一句話

**雲端模型讀得懂，錯幾乎都出在「沒拿到對的那一段」；功夫要花在讓它自己查得到，再用程式擋掉少數硬答。**
26 的數字：正解列全進依據時 Opus 221/223 對，沒全進時 3/158；有依據時它答出口的 342 次全對。〔雲〕

## 1. 量測：先有尺，再談做法

- **題庫 160 題起跳，每題帶一句原文當錨**，對錯用程式判（數字 1% 內＋單位；選型題按表的級距，選小一級另記為危險錯）。〔本，09、16〕
- **題目的字要照法規原文。** Opus 會因為題目把 110/220 V 寫成 120/240 V 而棄答，強模型會替你抓出壞題；壞題標 `defect` 整題不計，不事後改正解。〔雲，20〕
- **雜訊底線比本機模型小，但還是要量。** API 不收 temperature；同一份提示重跑，答案 Opus 88–91/91、Haiku 84–91/91 相同，回覆原文逐字相同的只有一半。**比答案，不要比原文。** 自己查的時候查詢字串每次都不同（Haiku 逐字相同 8/155），答案仍 143/155 相同。差距大於 .05 才算數。〔雲，20、27〕
- **上限（oracle）要給整欄或整張表，不要只給正解那一列。** 選型題要證明小一級不夠，只給一列時小心的模型會棄答，上限反而被低估（26：Opus oracle .93，自己查卻到 1.0）。〔雲，26、27〕
- **閉卷別當基線。** 提示裡「不要用自己知道的數值補」和「依你的知識回答」並存時，Haiku 全棄答、Opus 憑記憶答 .40——量到的是「它聽哪一句」。〔雲，26〕

## 2. 抽字：雲端模型讀表不挑格式

- **讀表那一步，給什麼都到頂。** 文字層、OCR 文字、乾淨頁圖、爛掃描（150 dpi、歪、模糊、JPEG q30），Opus 都是 82/82、Haiku .99–1.00，分不出。〔雲，25〕
- **掃描頁可以直接給頁圖，不必先 OCR。** 代價是每題貴 3～4 倍（Opus 文字 US$0.006 → 頁圖 US$0.024）。〔雲，25〕
- **但索引還是要文字。** 25 量的是「給對那張表後讀不讀得對」，不是檢索；要被查到，掃描頁仍要有文字（OCR 或文字層）。體檢那幾項（`(cid:N)` 亂碼頁、兩欄排版黏條號、橫式附表）影響的是索引，跟用哪個模型答無關。〔本，08、09〕

## 3. 切塊與索引：讓每張表「查得到、分得開」

- **條文一條一塊；每張表另做一張卡片**（表號＋表名＋副標＋欄名＋列鍵），卡片被查到就回**整張表**。〔雲，26、27 用的就是這個索引〕
- **清表時別丟副標。** 60／75／90℃ 三張表標題一字不差，副標一丟就分不開；補回後答對 +.15，比換任何找法都多。〔本，17〕
- **多份文件一起索引時，每塊帶《法規名》前綴。** 「哪一份規定了 X」的題沒前綴 .21、有 .94。〔本，10〕
- **一條一塊之後別再加花招**（標題鏈前綴、脈絡句、父子、混合檢索都分不出）。〔本，07〕

## 4. 檢索：給模型一支搜尋工具，讓它自己查

- **固定流程撈不全，自己查撈得全。** 同一個索引：一次 dense 撈全 .59、先拆子查詢再撈 .77；包成 `search` 工具讓模型自己查，Opus 1.0、Haiku .93。答對 Opus 127/127、Haiku .98，比最好的固定流程 +.24（分得出）。〔雲，26、27〕
- **法規庫變大也撐得住。** 從一部擴到六部相近的法規，答對、查詢次數、花費都幾乎不變；別部法規會被查到，但沒有一題拿它來答。〔雲，28〕
- **兩版比對：拿整條新條文當查詢，舊版對應的條幾乎都撈得到。** 條號全重排、兩版數字寫法不同，dense 撈全仍 .99–1.0，有沒有改、數值改多少答得跟直接給舊條文一樣準；錯的是官方對照表血緣跟內容不一致的列、和新增的條被硬配相近舊條。〔雲，29〕
- **它會自己拆兩張表的接力。** 「先查電動機滿載電流、算完再查導線表」這種題，模型會下兩條查詢；固定流程最常輸在這裡（C3：cards .08 → 自己查 1.0）。〔雲，27〕
- **工具的設定**（27 用的）：
  - 每次回約 3,000 字，查到卡片就展開整張表。
  - 上限 5 次；實際 Opus 平均 1.6 次、沒有一題用到 5 次，Haiku 1.9 次。超過上限回錯誤訊息「請直接回答」，最後一輪不再執行搜尋。
  - `strict: true` 的工具＋structured outputs 回答，兩者可同時用。
  - 開自動提示快取，記帳要分開算快取寫入（1.25 倍）與讀取（Opus 0.05 倍、Haiku 0.1 倍）。
  - 每輪把整個回覆（含思考區塊）原樣接回去，不然 API 回 400。
- **貴多少：** 每題約 2 倍、秒數約 2 倍。Opus US$0.038（固定檢索 0.018），Haiku US$0.0013（0.0005）；秒數中位 5 秒（固定 2.5 秒）。〔雲，27〕
- **重排器**（bge-reranker-v2-m3，固定檢索 +.05 答對）在自己查的流程裡有沒有用，沒量。〔本，12〕

## 5. 回答的格式

- **schema 裡放 `found` 布林、`value`、`unit`、`quote`。** 格式不是問題：25–27 的回覆解析失敗都是 0。〔雲〕
- **讀表不用替它做查表工具。** Opus 整張表 .99、查表工具 1.0，分不出；小模型才需要程式替它點格子。〔雲，20〕

## 6. 程式層要擋的（模型做不到自己擋）

| 要擋什麼 | 量到的 | 怎麼擋 |
|---|---|---|
| 檢索沒撈到東西就叫模型答 | Opus 閉卷答 74 題錯 23（其中 5 題選小一級），錯得很有自信〔雲，26〕 | 一次都沒查到相關的就不給答，回「找不到」 |
| 表格空白格硬答 | Haiku 自己查時兩次各 2 題拿鄰欄推值；固定檢索時沒有〔雲，27〕 | `quote` 指到的那一格是空白就改判棄答 |
| 選小一級（危險錯） | Haiku 26 有 5 次、27 每次 1 次；Opus 0 次〔雲〕 | 程式驗算：選出的線徑載流量 ≥ 需求電流，不夠就退回 |
| 引句是不是來自查到的文字 | 逐字比只對 9–16/128（模型會把表頭和列改寫成一行）〔雲，27〕 | **比數字，不比字串**：引句裡的數字都要出現在查回來的文字裡；它自己算的數（例：需求電流 19.25 A）另外驗算 |

## 7. 選哪個模型

- **Haiku 5.5 便宜 25～36 倍，答對差 .00–.02**：固定檢索時跟 Opus 同分（cards .61 對 .61），自己查時 .98 對 1.0。〔雲，26、27〕
- **差別在錯的樣子**：Haiku 會選小一級、會在空白格硬答；Opus 這兩種都沒有。
- 我的建議（不是量出來的）：**預設用 Haiku＋第 6 節的程式守門；錯一題代價很高、或規則例外多的場合用 Opus。** 160 題、一題一次的量級，Opus 自己查全跑一遍約 US$6、Haiku 約 US$0.2。

## 8. 本機小模型時代的修法，換雲端後不用做

| 修法 | 本機時為什麼要 | 雲端上 |
|---|---|---|
| 調 glm-ocr 提示、縮圖、攤平 OCR 表頭（06、22–24） | 小模型讀 OCR 表會掉分 | 給頁圖或 OCR 文字都到頂（25） |
| 表格轉 markdown／逐列鍵值（03、18） | 攤平文字讀錯欄 | 25 的四種給法都 82/82；沒單獨比格式 |
| 查表工具回一格、回整欄（19、21） | 小模型選錯列、分段漏段 | Opus 整張表就 .99（20） |
| 規則寫成函式、只讓模型填參數（16） | 小模型停在中間值、分段當一個係數 | 有依據時答出口的幾乎全對（26） |

## 9. 還沒量過、上線前要補的

- **更大、更亂的語料。** 28 加到六部相近的法規（2,277 條、153 張表、字數約 2 倍）沒有變差（Opus 127/127、Haiku 在雜訊內），但連固定檢索都沒掉，表示干擾還太遠；同一規則的舊版、CNS 這類也有安培容量表的文件、上千頁時不一定。系統提示點名了法規舊名，拿掉後沒量。
- **更難的題**：三張表以上接力、真的規格書與圖面。版本比對題 29 量了「附新條文全文、查舊版」這一種，太容易（撈全 .99–1.0）；只給條號不附全文、兩版同一索引、問刪了哪幾條、附表裡的數值，都沒量。
- 掃描頁進索引（OCR 對檢索的影響）只在本機流程量過；ColPali 這類「用頁圖檢索」沒試。
- 搜尋上限降到 2–3 次、effort low、Sonnet 5.5、其他供應商，都沒試。
- Opus 自己查只跑一次，沒有它自己的雜訊底線。
